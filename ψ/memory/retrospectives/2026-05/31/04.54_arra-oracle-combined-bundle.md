## AI Diary
This session was a long, branchy build that kept revealing that "green" is not "correct." I designed a clean dual-mode architecture (runtime base context so one compiled component works at `/` standalone and `/studio` combined) and ran it through a 10-agent workflow that came back all-green: 7 standalone builds, the combined build, and a grep alias-invariant showing no stray `react-router-dom` Link imports. I reported it as working. [→ AGENT DECISION] I declared the combined bundle's navigation correct on the strength of build-green + the grep invariant, without ever rendering the nav — and the user immediately found that every menu item still bounced cross-origin to `feed.buildwithoracle.com`. The grep invariant proved imports were clean; it could not see that `MainNav` computed the cross-origin `<a href>` *before* the in-app `<Link>` branch, so on the `app.*` origin the `<a>` always won. The fix was one line per component, but the lesson stings: I had a browser-automation tool (dev-browser) available the whole time and only used it *after* the user reported the bug — when I finally drove it standalone, it printed "15 nav links, 0 cross-origin" in seconds. I also let the host-default policy churn (added a `*.buildwithoracle.com→localhost` carve-out, then the user wanted unconditional localhost) instead of asking the policy up front. The wins were real — the architecture held, the loop bug I caught *before* deploy, and the backend CORS/PNA trace prevented a wild goose chase — but my proof discipline lagged my build discipline.

## Honest Feedback (session-specific friction)
1. **`bun --cwd` is broken in this repo's bun canary (1.4.0-canary.1)** — every root `deploy:X` / `build:all` / `deploy:all` script silently fails (prints `bun run` help). I lost a cycle discovering it and had to use `bun run --filter <pkg>` everywhere, including in every workflow agent prompt. The committed root scripts are effectively dead in this environment.
2. **Wrangler OAuth expired across the midnight boundary** mid-redeploy — 6h gap then `auth error 10000`. Re-login then failed once with an OAuth state-mismatch because a backgrounded `wrangler login` left port 8976's callback server lingering. Two dead ends before the redeploy ran.
3. **rtk grep hook corrupted subagent grep output** (`"N matches in N files"` with bogus lines) — workflow verify/find agents had to fall back to `rtk proxy grep` / `command grep`, and flagged it as an unreliable invariant source.

## Lessons Learned (generalizable)
- **Build-green + static invariants ≠ behavior-correct.** A grep/lint invariant proves imports compile and are clean; it cannot prove rendered UI behavior. For nav/routing changes, render it (browser or dev-browser) before claiming it works — especially when a tool is already available.
- **A deployed thin client must default its backend to `localhost`, not the page hostname.** The deployed origin can never serve the local `:47778` backend; deriving host from `window.location.hostname` only makes sense for LAN/dev hostnames, and even then `?host=` covers it.
- **When merging N hostname-identified SPAs into one origin, the real blocker is identity-by-hostname.** Convert to identity-by-path, and check branch *order*: any cross-origin href computed before the in-app link will win and silently escape the bundle.
